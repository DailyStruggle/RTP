### 6.2 Live Poller Integration Bugs Discovered & Fixed During Live Parity Testing

Running the full 69-test suite through the real Discord REST API v10 and `DiscordForumPoller.poll_once()` exposed two live-only poller discrepancies that offline unit tests on `SupportBotEngine` alone did not catch:

1. **Text Attachment Extraction & Signed Discord CDN URL Query Parameters (`discord_support_bot.py` lines `712`, `5620`):**
   - **Symptom on Live Discord (`th_cdn_log` / `th_yml_1`):** When a `.log`, `.txt`, or `.yml` file was uploaded as a real Discord message attachment, Discord returned a signed CDN URL (`https://cdn.discordapp.com/attachments/.../latest.log?ex=...&is=...&hm=...`). `DiscordForumPoller.poll_once()` previously only called `extract_image_attachment_urls(m)` (ignoring `extract_text_attachment_urls(m)`), and `fetch_text_attachment` checked `url.endswith((".yml", ".yaml", ".txt", ".log"))` on the full URL string (which failed when `?ex=...` query parameters were appended by Discord's CDN).
   - **Fix Applied:** Added `extract_text_attachment_urls(m)` in `DiscordForumPoller.poll_once()` (`Case 1` and `Case 2`) and parsed `urllib.parse.urlparse(u).path.lower()` before checking `.yml`/`.yaml`/`.txt`/`.log` extensions in `fetch_text_attachment`.

2. **Evaluated-Message Watermark Across Silent Follow-Up Turns (`discord_support_bot.py` lines `5015`, `5680-5715`):**
   - **Symptom on Live Discord (`th_hostile_1` / `th_refuse_1`):** When a user posted a follow-up turn where `SupportBotEngine.handle_followup_message` intentionally returned `should_reply = False` (such as a second zero-delta refusal after the one-time grace reply, or a hostile outburst with no new diagnostics), no new bot message was added to Discord (`bot_indices` did not advance). On the next user message (Turn 4), `DiscordForumPoller.poll_once()` re-collected all messages after `last_bot_idx`, re-concatenating the already-evaluated Turn 3 message into Turn 4.
   - **Fix Applied:** Added `thread_last_evaluated_msg_id: dict[str, str]` (persisted in `bot-state.json`) so `DiscordForumPoller.poll_once()` advances the per-thread message watermark after every evaluated follow-up turn (unless deferred by per-user cooldown) and only passes newly arrived messages since `thread_last_evaluated_msg_id[thread_id]` into `handle_followup_message`.
