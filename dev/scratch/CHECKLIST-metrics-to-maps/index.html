    • [x] 1.7 rtp-core/.../commands/maps/BadPointsHeatmapResolver.java (placed flat in commands/maps, not a resolvers/ subpackage). Every failure path logs WARNING via RTP.log (S-004). Single-tile allocation only in Stage 1; tile counts on ChartSpec recorded but not forwarded to MapBinding.allocate (mosaic deferred). When item 2.1 lands, expect to add a record OpenMap(UUID chartSpecToken) implements MenuAction to the permits list rather than an enum constant; downstream dispatch sites are exhaustive switch over the sealed type, not a Kind table.

    Notes / open questions¶

    • Permission scoping. Stage 2 step 2.9 assumes an existing admin permission on the /rtp info admin subtree. Confirm against RtpAdminPermissions and the current InfoCmd permission gate before authoring; if absent, add rtp.admin.chart under the existing permission node convention and document in messages.yml admin help text.
    • MapBinding slot in RTPHooks. Owned by CHECKLIST-maps-api.md Stage 2.6. If that row slips, Stage 2 of this checklist still ships — the menu entry is simply absent at runtime. Do not duplicate the hook here.
    • Token TTL default (60 s). Picked to match the existing menu-redeem token. If admins report timeouts, raise to 300 s; not a hard requirement.
    • HeatmapRenderer.INSTANCE. The single concrete renderer Stage 1 references. If HeatmapRenderer is not currently a singleton, Stage 1 step 1.8 adds public static final HeatmapRenderer INSTANCE = new HeatmapRenderer(); (stateless, safe). Cross-reference maps-api/src/main/java/.../mapsapi/render/HeatmapRenderer.java before authoring.
    • Cap default (250 000 bad-points reads). Conservative; covers ~10× the typical long-running-server badKeysCache size observed in stress tests. Make configurable from day one (performance.yml key chartBadPointsCap) to avoid a follow-up edit.
    • No new I/O. Re-asserted: every Stage 1 + Stage 3 resolver reads only in-memory state. No world.getChunkAt, no DB query, no anvil scan. This is the load-bearing S-005 invariant for the whole bridge.
