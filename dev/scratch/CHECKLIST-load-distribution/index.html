    CHECKLIST: Load distribution across backends¶

    Effective Issue: have the proxy pick the best backend (lowest load, healthy, eligible) among N rather than just a backend, with operator-visible rationale and anti-flap behavior.

    Mode: [CODE] (multi-slice, will need D-005 proposals per slice).

    Anchors: MULTI_SERVER_PLAN.md Phase 2 selector items; GLOSSARY.md Backend Selector; REQ-RTP-NET-010 / -011; WeightedAverageBackendSelector (existing).

    Hard prerequisite: cross-server frontier (CHECKLIST-cross-server-rtp.md L1-L3) must be green. Load distribution is meaningless without a working second-JVM hop to distribute to.

    Reconciled-in from CHECKLIST-metrics-and-multiserver.md (2026-05-20): D5 (curve plot generation script) + D6 (LOAD_BALANCING.md admin doc) folded into D8 below; E8 (recentPicks halflife=10s decay) folded into D2 as a selector-tuning row.

    Reconciled-in from PROPOSAL-velocity-redis-startup.md (2026-05-20, file since deleted): PROPOSAL was silent on selector internals (out of its scope per §10); only relevant touchpoint was §8 OQ6 (killSwitch field placement), folded into D5 row 33 (now reworded to point at the cross-server checklist's open OQ6 row instead). PROPOSAL file deleted 2026-05-20; failure-mode policy lives at MULTI_SERVER_PLAN.md §Failure-Mode Policy (network-mode bootstrap).

    Prerequisites already shipped (do not redo): - [x] 0a. BackendSelector SPI + WeightedAverageBackendSelector implementation present. - [x] 0b. BackendHeartbeat schema includes tps, mspt, playersOnline, pendingQueue, keptCacheSize, killSwitch. - [x] 0c. HMAC-signed heartbeats over Redis + SQL (A3, 2026-05-20). - [x] 0d. NetworkSnapshot exposed to dispatcher path.

    D1. Heartbeat field completeness (~1-2h)¶

    • [ ] 1. D-005 proposal for D1 (affected: NetworkModeBootstrap heartbeat loop, BackendHeartbeat field producers on backends).
    • [ ] 2. Audit NetworkModeBootstrap.publishHeartbeat (or equivalent) for every field WeightedAverageBackendSelector reads. Document current source per field in the proposal.
    • [ ] 3. tps / mspt: source from local TPS sampler (metrics-api if running, else fallback to a 1-tick deltaT averager - recommend the same one used by /rtp status).
    • [ ] 4. playersOnline: Bukkit.getOnlinePlayers().size() on Paper, Folia equivalent (must avoid main-thread block per S-005 if not already on a tick thread).
    • [ ] 5. pendingQueue: read from RegionQueueManager.playerQueue.size() (the teleport waitlist, not the personal-queue bucket - see GLOSSARY canonical alias).
    • [ ] 6. keptCacheSize: RegionQueueManager.keptLocations.size() (hot/L1 queue per .junie/AGENTS.md Domain Analogies table).
    • [ ] 7. killSwitch: read from network.yml runtime knob (already wired post-OQ6); confirm propagates to heartbeat encode.
    • [ ] 8. Unit test: synthetic backend produces a heartbeat with all six fields non-zero (or explicitly justified zero).
    • [ ] 9. :rtp-plugin:test + .\gradlew build green.

    D2. WeightedAverageBackendSelector real-traffic shakeout (~2-3h)¶

    • [ ] 10. D-005 proposal for D2 (affected: WeightedAverageBackendSelector, new selector block in network.yml).
    • [ ] 11. network.yml selector block: weight.tps (default 1.0), weight.mspt (default 1.0), weight.queueDepth (default 0.5), weight.playerCount (default 0.25). Pin defaults in an ADR (new rtp-proxy-ADR-012-selector-weight-defaults.md).
    • [ ] 12. Selector reads weights from config; falls back to defaults if unset (REQ-RTP-NET-002 disabled-no-op preserved).
    • [ ] 13. Locale parity sweep on the new network.yml keys: run the TSV pipeline (locale-files-to-csv -> reconcile-locale-csvs -> translate -> locale-files-from-csv -> LocaleParityTest).
    • [ ] 14. Drive selector from a synthetic 4-backend NetworkSnapshot (one slow, three fast) and assert distribution converges within 10 picks per spec (TBD: pin threshold in ADR).
    • [ ] 15. Verify weight curves at boundary conditions (tps=0, mspt=200ms, queueDepth=Integer.MAX_VALUE) don't NaN or IllegalArgumentException.
    • [ ] 16. Unit test: weight-mix produces deterministic ordering for deterministic input.
    • [ ] 17. (absorbed from metrics+multiserver E8) recentPicks halflife=10s decay (lambda ~= 0.0693 s^-1) integrated as a selector metric row. Unit test: synthetic clock asserts score returns to background within ~30s after a single pick.
    • [ ] 18. :rtp-proxy:rtp-proxy-common:test + .\gradlew build green.

    D3. Affinity / stickiness policy (~2-3h, design decision)¶

    • [ ] 19. D-005 proposal for D3 (affected: new PlayerAffinityCache, new selector.affinity config block, WeightedAverageBackendSelector hook).
    • [ ] 20. Decide policy default. Recommended: soft with configurable threshold (selector.affinity.mode: soft, selector.affinity.threshold: 0.15 meaning "prefer original if within 15% load of best"). Other options: none (pure least-loaded), hard (always original until original unhealthy).
    • [ ] 21. New PlayerAffinityCache: TTL-bounded (default 24h), transport-backed key rtp:aff:<uuid> (Redis) / rtp_network_affinity table (SQL). Survives proxy restart.
    • [ ] 22. Affinity hook: selector calls cache.lastBackend(uuid) before final pick; applies threshold per policy.
    • [ ] 23. On successful teleport: dispatcher writes cache.recordTeleport(uuid, backendId) after redemption confirmed.
    • [ ] 24. Unit test: same player picks same backend under load equilibrium; switches to different backend when threshold exceeded.
    • [ ] 25. ADR: rtp-proxy-ADR-013-player-affinity-policy.md documenting the three modes and the recommended default.

    D4. Hysteresis / anti-flap (~1-2h)¶

    • [ ] 26. D-005 proposal for D4 (affected: WeightedAverageBackendSelector selection loop).
    • [ ] 27. Configurable minimum-weight-delta threshold (selector.hysteresisDelta, default 0.05). Below threshold, prefer the previous winner.
    • [ ] 28. Per-proxy lastWinner cache (in-memory, not transport-backed - flapping is a per-proxy concern).
    • [ ] 29. Unit test: two backends with weights differing by < threshold -> selector stays on the previous winner across N picks.

    D5. Per-backend exclusion (killSwitch granularity, ~1h)¶

    • [ ] 30. D-005 proposal for D5 (affected: BackendHeartbeat already has killSwitch; selector must honor it as exclude-this-backend, not halt-all).
    • [ ] 31. Confirm semantic: killSwitch:true on a backend's heartbeat -> selector drops it from candidates (rolling-restart use case). killSwitch:true on a proxy's heartbeat -> halt all dispatch from that proxy (existing semantic).
    • [ ] 32. Unit test: 4-backend snapshot with one killSwitch:true -> selector picks among the remaining 3, never the excluded one.
    • [ ] 33. Document the two-tier killSwitch semantic (per-backend exclude vs per-proxy halt-all) in rtp-proxy-ADR-010 (security hardening) or a new selector ADR; resolves the open OQ6 row tracked on CHECKLIST-cross-server-rtp.md L5 row 35.

    Out of scope (defer)¶

    • Per-region / per-world load awareness (selector is currently backend-grained).
    • Predictive load modeling (e.g. EWMA over heartbeat history) - pure instantaneous selection for v1.
    • Cost-based selector (latency to player's geographic region) - needs IP geolocation, out of scope.
    • Metrics axis integration (METRICS_PLAN.md) - orthogonal; selector reads NetworkSnapshot directly.
