    CHECKLIST - beta.4 Locale Translation Pass¶

    Effective Issue: Land all shipped-locale translations before publishing beta.4. Mode: [CODE] (multi-session, resumable) Source of truth: scripts/out/locale-<lang>.tsv (edit these, not the YAML tree). Pipeline: edit baseline -> locale-files-to-csv -> scan-locale-untranslated -> author scripts/translations/<lang>.tsv -> apply-locale-translations -> locale-files-from-csv -> LocaleParityTest + .\gradlew build.

    Helper script: apply-locale-translations.ps1¶

    Authored 2026-05-22 to make per-locale batches tractable. Curated translations live in scripts/translations/<locale>.tsv (one file per locale), schema:

    relpath  parent_path  base_key  index  new_key  new_value  new_comment
    • parent_path is REQUIRED for disambiguation (port, host, type, k etc. legitimately repeat across nested YAML sections).
    • Empty new_* columns = keep current; <empty> sentinel = clear the column.
    • Atomic: any unresolved row aborts the whole write.
    • Idempotent: re-running with already-applied rows is a no-op.

    Usage:

    .\scripts\apply-locale-translations.ps1 -Locale cat -DryRun
.\scripts\apply-locale-translations.ps1 -Locale cat

    Per user direction (2026-05-22), identity-legitimate rows (YAML keys like host/port/type, language-agnostic enum tokens, doc-tag-only comments) are omitted from the translations TSV rather than documented with sentinel rows. The scanner is first-pass triage, not an audit log.

    Process per locale (repeat for each, one yml file at a time per user direction 2026-05-22)¶

    For each locale <L>, batch by source YAML file (messages.yml first - highest player-visible impact; then config.yml, safety.yml, economy.yml, effects.yml, logging.yml, performance.yml, regions.yml, worlds.yml, network.yml, shape/vert rename-maps):

    • [ ] 1. Refresh TSVs: .\scripts\locale-files-to-csv.ps1 (only if baseline YAML changed since last run).
    • [ ] 2. Refresh triage: .\scripts\scan-locale-untranslated.ps1 -Locales <L> -SampleCount 0. Record counts in the table above.
    • [ ] 3. Author/extend scripts\translations\<L>.tsv for the current yml file's rows. Schema in the Helper-script section above. Respect masking rules for [placeholders], &a/#hex colors, \u00A7 markers, @type/@range/@unit/@default/@options doc-tags, URLs, version banners. Omit identity-legitimate rows (YAML keys, language-agnostic values, doc-tag-only comments).
    • [ ] 4. Dry-run: .\scripts\apply-locale-translations.ps1 -Locale <L> -DryRun. Inspect planned changes.
    • [ ] 5. Apply: .\scripts\apply-locale-translations.ps1 -Locale <L>.
    • [ ] 6. Regenerate YAML tree: .\scripts\locale-files-from-csv.ps1.
    • [ ] 7. Parity: .\gradlew :rtp-plugin:test --tests "*LocaleParityTest*".
    • [ ] 8. If <L> == es: also .\gradlew :rtp-plugin:test --tests "*ReqRtpF013SpanishLocaleContentTest*".
    • [ ] 9. Spot-check rendering against AGENTS.md "Book Menu Color Contrast" if any menu strings were touched.
    • [ ] 10. Commit scripts\translations\<L>.tsv + scripts\out\locale-<L>.tsv + regenerated lang/<L>/**.yml + <file>.lang.yml.

    Resume protocol¶

    A fresh agent resuming this task should:

    1. Read this file top to bottom.
    2. Run step 2 (scan-locale-untranslated) to confirm the snapshot table still reflects reality; update the table if drift is observed.
    3. Pick the first unticked per-locale box and start from step 1 of the per-locale process.
    4. Never tick a box speculatively - only after the cited command/test passes.

    Hard rules (do not violate)¶

    • Do NOT hand-edit lang/<L>/*.yml or *.lang.yml. The TSV is the source of truth; reconcile will overwrite hand-edits.
    • Do NOT pivot translations through another locale's translated key - always translate from baseline base_key / English value.
    • cat locale is Internet Cat dialect, NOT Catalan (ISO ca is unrelated). Mirror existing cat-themed vocabulary.
    • Mojibake check: before submit, search the diff for \u00C3, \u00C2, \u00E2\u20AC, \uFFFD. Any hit is a defect.
    • Stay on task: incidental bugs go to docs/dev/POTENTIAL_BUGS.md, not fixed inline.
