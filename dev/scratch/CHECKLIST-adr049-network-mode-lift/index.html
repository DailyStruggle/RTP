    CHECKLIST: ADR-049 network-mode platform-neutral lift¶

    Effective Issue: Continue ADR-049 implementation so Fabric can function as either a lobby or backend in network mode (request and receive cross-server teleports).

    ADR: docs/adr/ADR-049-network-mode-platform-neutral-lift.md (Accepted 2026-05-23; step-4 addendum added 2026-05-23 widening SPI surface).

    Devstack acceptance: user-driven per explicit user direction; not a checklist step the agent runs.

    Delete this file when step 13 is complete and submitted.

    Done¶

    • [x] 1. PlayerLifecycleHook SPI in rtp-api (interface + NoopPlayerLifecycleHook + DispatchingPlayerLifecycleHook + RTPServerAccessor.getPlayerLifecycleHook() default). Evidence: rtp-api/src/main/java/io/github/dailystruggle/rtp/api/server/PlayerLifecycleHook.java, NoopPlayerLifecycleHook.java, DispatchingPlayerLifecycleHook.java. :rtp-api:build green.
    • [x] 2. BukkitPlayerLifecycleHook shim in rtp-bukkit-common; AbstractServerAccessor owns + registers it on start(Object). Evidence: BukkitPlayerLifecycleHook.java, AbstractServerAccessor.java. :rtp-bukkit-common:compileJava green.

Evidence: FabricPlayerLifecycleHook.java, FabricServerAccessor.java, FabricEventBridge.java. :rtp-fabric-common:compileJava green.

    Deferred (Fabric follow-up)¶

    • Fabric waitlist command-guard: blocking a fresh /rtp while a player is already enrolled. Bukkit gates this via RTPCmdBukkit.addSenderCheck(Predicate<CommandSender>); the Fabric Brigadier tree (RTPCmdFabricRoot/BaseRTPCmdImpl) has no equivalent sender-check insertion point. The reservation-token redeem path (the core Phase 2 value) is complete and unaffected; a platform-neutral guard would thread the predicate into shared RTPCmd.compute (touches the working Paper path) - left as a follow-up.
