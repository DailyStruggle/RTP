    Checklist - NeoForge Phase N2 (platform-adapter implementation, Fabric parity)¶

    Editable scratch working note (per Checklist-Based State Tracking in .junie/AGENTS.md). Delete on submit once the work lands, or fold into MULTI_PLATFORM_PLAN.md Phase 4. This file tracks bringing the Phase N1 NeoForge skeleton up to runtime parity with rtp-fabric-common.

    Effective Issue: Check the Fabric implementations and create a scratch checklist for the (Neo)Forge implementation. Mode: [CODE] (this note is the planning artifact; coding is the follow-up). Owner: project lead (@leaf_26). Gates: Phase N0 (D-005 proposal APPROVED 2026-06-01) and Phase N1 (module skeleton landed 2026-06-02) are complete. Phase N2 is unblocked.

    Build precondition (every box below): NeoForge/ModDevGradle userdev artifacts require network access. All compile/test verification must run on a network-capable host via: .\gradlew -PincludeNeoforge :rtp-neoforge:rtp-neoforge-v1_21_R1:build Nothing in N2 can be proven green in the offline sandbox.

    Steps (ordered so a fresh agent can resume from the first unchecked box)¶

    N2.0 - version-adapter SPI in common¶

    • [x] 1. Authored NeoForgeVersionAdapter + NeoForgeVersionAdapterRegistry in rtp-neoforge-common (ported from Fabric; trimmed of not-yet-ported effects/menu seams). Evidence: platforms/rtp-neoforge/rtp-neoforge-common/src/main/java/io/github/dailystruggle/rtp/neoforge/version/. Note: unlike Fabric, the SPI's chunk/level seam passes net.minecraft ServerLevel/ChunkAccess directly - the RTPLevelHandle/RTPChunkHandle Object-boxing wrappers were dropped because NeoForge is Mojmap-at-runtime (single mapping, stable class names; no obf/intermediary split that forced the Fabric wrappers per rtp-fabric-ADR-007).
    • [x] 2. Implemented V1_21_R1NeoForgeVersionAdapter against 1.21.1 Mojmap: typed BuiltInRegistries.BLOCK tag walk, S-005 async ServerChunkCache#getChunkFuture path with temp load-ticket, non-persistent TicketType region tickets (distance 3, reflective package-private DistanceManager resolution; rtp-fabric-ADR-006 port), and typed player/console seams. Evidence: platforms/rtp-neoforge/rtp-neoforge-v1_21_R1/.../V1_21_R1NeoForgeVersionAdapter.java. Bootstrap wiring added: RTPNeoForgeMod#installVersionAdapter reflectively resolves+installs the carrier at server-start (S-006 fail-loud), and onServerTick drives tickRefresh. Unverified offline (NeoForge/ModDevGradle build needs network). The Entity#teleportTo/TeleportTransition call moves to the server accessor / world (step 3-4), not the SPI.

All abstract RTPServerAccessor methods covered; remaining interface methods are default. Player lifecycle hook is a NoopPlayerLifecycleHook placeholder until N2.3. Evidence: platforms/rtp-neoforge/rtp-neoforge-common/src/main/java/io/github/dailystruggle/rtp/neoforge/server/NeoForgeServerAccessor.java. Offline lint clean; NeoForge compile unverified (network-gated -PincludeNeoforge).
    • [x] 4. NeoForgeRTPWorld / NeoForgeRTPChunk (ported) wired to the N2.0 async chunk SPI (requestFullChunkAsync/applyTicket/releaseTicket passing ServerLevel/ChunkAccess directly); ADR-016 anvil pre-filter, S-002 non-persistent tickets via the adapter. Evidence: .../neoforge/world/.
    • [x] 5. NeoForgeRTPPlayer (ported, trimmed): identity, chat/title/actionbar via ClientboundSystemChatPacket+packets, version-robust teleport, location, online status, op-level hasPermission via on-disk ops.json (full perms N2.5).     N2.2 - binding into RTP API¶

    • [x] 6. RTPNeoForgeMod.onServerStarted -> bootCore: constructs NeoForgeServerAccessor, sets RTP.serverAccessor, assigns RTP.scheduler = accessor.getScheduler() before new RTP() (rtp-core constructor self-schedules pipeline/DB timers via the scheduler), bindServer(server) (rebuilds block-tag snapshot), schedules the non-Folia ChunkUnloadProcessor timer (S-002), and drains RTP.startupTasks (sync + +1-tick + sync, mirroring Bukkit/Fabric). onServerStopping unbinds the accessor (stops scheduler + clears maps); the final mutation drain is rtp-core's RTPRunnable shutdown (DB kill/network teardown deferred to N2.3). onServerTick now drains the accessor's own scheduler (the duplicate NeoForgeScheduler field was removed) and refreshes carrier tickets. Bootstrap wrapped in try/throwable -> RTP.log(SEVERE) (S-004 loud-fail). Evidence: RTPNeoForgeMod.java. Offline lint clean; NeoForge compile unverified (network-gated -PincludeNeoforge).

    Notes / known constraints¶

    • Mojmap-at-runtime (1.20.4+): NeoForge ships Mojang-mapped names at runtime, so - unlike rtp-fabric - there is no obf/unobf carrier split. Only one carrier per MC line is needed (rtp-neoforge-ADR-001, NEOFORGE_NOTES.md).
    • Scheduler rule: all periodic/async work goes through RTP.scheduler (the NeoForgeScheduler). No raw Executors/Thread in rtp-neoforge-* (the scheduler impl itself is the documented carve-out).
    • Opt-in island: verification only works with -PincludeNeoforge; the default offline build excludes these modules by design (settings.gradle).
    • Carrier roadmap (from platforms/rtp-neoforge/README.md): v1_21_R1 (1.21.1) is the Phase N2 reference target. The v26_1_R1 carrier (MC 26.1.2 / NeoForge 26.1.2.65-beta) is now authored (2026-06-03, EARLY/EXPERIMENTAL) - a faithful clone of the 1.21.1 carrier, Java 25, gated under -PexcludeJdk25; RTPNeoForgeMod routes 26.* to it. It is NOT runtime-verified (network-gated NeoForge 26.1 userdev; maintainer builds on a JDK-25 host and re-pins versions when 26.1 settles). No separate rolling-1.21.x-head carrier is needed: startsWith("1.21") already serves the whole 1.21 line from v1_21_R1 (Mojmap names stable across 1.21.x). 1.20.1 stays out of scope (Forge ecosystem).
    • Largest single task is step 3 (the RTPServerAccessor port); budget accordingly and lean on the Fabric file as a line-by-line template since rtp-api was confirmed sufficient for non-Bukkit platforms.
