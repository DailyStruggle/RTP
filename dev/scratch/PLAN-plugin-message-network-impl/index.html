    PLAN - Plugin-Message Network Transport implementation¶

    Status: In progress - Slices A-H landed; Slice G complete (liteJarStructureCheck now excludes/forbids the proxy/common/transport/{redis,sql}/ subtrees that were leaking into lite and asserts the plugin-message binding/resolver present; check passes) and Slice H complete (Velocity audit: the BungeeCord vocabulary is handled natively by Velocity core, no proxy code needed; finding recorded in rtp-proxy-ADR-016); Slice B item 7 (Bukkit shim) + Slice D item 19 landed so the tier-1 transport is live on Bukkit/Paper/Folia; Slice I (docs/CHANGELOG sync + final gate), the command-tree wiring of NetworkRegionParameter, and the deferred Fabric/NeoForge shims (item 8) remain (see per-slice boxes + the progress note below).

    Progress note (2026-06-12): Slice A (shared BackendHeartbeatCodec, Redis+SQL repointed), Slice B item 6/9 (NetworkBridge seam + inline FakeNetworkBridge), Slice C (PluginMessageNetworkBinding + tests), a minimal item 19 (RTP.networkBridgeFactory hook + plugin-message/auto cases in NetworkModeBootstrap.openTransport, auto resolves silently to disabled with no proxy bridge), and the Slice D state machine (ProxyAutoDetector items 16-18 + the NetworkBridge.requestTopology()/registerTopology()/Topology active-handshake default methods, ProxyAutoDetectorTest 5/5, item 20) are implemented and verified by .\gradlew build. Still open: the Bukkit NetworkBridge shim (Slice B item 7) and the full bootstrap wiring that constructs/pumps ProxyAutoDetector and resolves auto to plugin-message on ENABLED (item 19 full), NetworkRegionParameter (E), network.yml schema + locale pipeline (F), lite-jar audit extension (G), Velocity channel handling (H), and the docs/CHANGELOG sync (I). Progress note (2026-06-13, Option 1 - topology-seeded candidates): Symptom "only /rtp region=default works on a lobby" root-caused to the single-player plugin-message gossip limitation: a player-empty backend cannot carry its heartbeat, so the heartbeat-fed NetworkSnapshot (the sole source for PeerRegionRegistry.peerEntries()/isReachableHardPin) stays empty on the lite tier and every server:region destination is rejected/unsuggested. Owner (leaf) chose Option 1: seed cross-server destinations from the proxy's GetServers topology (only needs the local server's own player connection). Implemented in PeerRegionRegistry (new setTopologyPeerSupplier/setAssumedRegionSupplier; peerEntries() surfaces server:default for proxy-advertised peers lacking a heartbeat, isReachableHardPin accepts topology-known servers under "unknown -> accept" while a live killSwitch or a concrete heartbeat region set still wins) and wired in NetworkModeBootstrap from ProxyAutoDetector.peerServerIds(). New PeerRegionRegistryTest topology cases + existing suites green; full .\gradlew build green. (Blank /rtp lobby dispatch via pickMostKept() still needs real heartbeat metrics and is out of this fix's scope.)

    0. Anchored seams (verified in the codebase)¶

    • rtp-core -> NetworkModeBootstrap.openTransport(type, intervalMs, transportSec, verifier, schemaVersion) is the single switch that constructs a NetworkTransport from transport.type. It currently handles in-memory / sql / redis. This is where plugin-message and auto plug in.
    • rtp-proxy-common -> NetworkBindings.open(cfg, dataSource) is the proxy-side factory mirror of the same switch (used by the Velocity/Bungee adapters). Keep the two switches in sync.
    • InMemoryNetworkStateBinding implements NetworkTransport is the reference peer to mirror: methods publishBackendHeartbeat, readSnapshot, subscribeBackendHeartbeats, claim/release/redeem/findReservation/reapExpired/listActiveForServer, publishProxyHeartbeat, close.
    • RedisNetworkStateBinding.encodeBackend(BackendHeartbeat) (+ the matching decode) is private; SqlNetworkStateBinding already duplicates the same field order. Both must move to a shared codec before tier-1 can reuse it (Slice A).
    • transport.type is parsed by NetworkConfig (proxy side) and read from RtpYamlSection in NetworkModeBootstrap (backend side).

    • [x] 1. Add BackendHeartbeatCodec in rtp-proxy-common (...transport.codec), with encode(BackendHeartbeat): String / decode(String): BackendHeartbeat, lifted verbatim from RedisNetworkStateBinding.encodeBackend/decode (preserve exact field order - the HMAC in Redis signs over it).
    • [x] 2. Repoint RedisNetworkStateBinding to call the shared codec; delete its private copies. Keep the HMAC layer wrapping the codec output unchanged (codec must stay HMAC-agnostic).
    • [x] 3. Repoint SqlNetworkStateBinding (line ~543, "order matches RedisNetworkStateBinding.encodeBackend") to the shared codec.
    • [x] 4. Tests: a BackendHeartbeatCodecRoundTripTest (encode->decode identity for a fully-populated BackendHeartbeat, incl. empty/optional fields); run existing RedisNetworkStateBinding* and SqlNetworkStateBinding* suites to prove no regression.

    Risk: field-order drift breaks the Redis HMAC. Mitigation: codec is byte-identical to the old private method; round-trip + existing Redis signed-snapshot test guard it.

    Slice H - Velocity channel handling (decision §9.4: implement if absent)¶

    Goal: ensure the proxy honors GetServer/GetServers/Connect/Forward on modern Velocity (proposal §9.4). BungeeCord is layered later, not this turn.

    • [x] 30. Audit rtp-proxy-velocity for the modern namespaced channel registration + the GetServers/topology handshake; add whatever is missing. Done (no code change required): the audit found rtp-proxy-velocity registers/handles no plugin-message channel at all - it operates purely at the SPI/transport level (Redis/SQL/in-memory state, dispatcher, ServerPreConnectEvent redeem). Modern Velocity honors the full BungeeCord vocabulary (Connect/ConnectOther/GetServer/GetServers/Forward/ForwardToPlayer) via its own built-in handler on bungeecord:main, gated by bungee-plugin-message-channel = true in velocity.toml (the default). The backend BukkitNetworkBridge (Slice B item 7) speaks to that native handler directly and receives replies/forwards on its registered incoming bungeecord:main channel, so nothing was missing on the proxy side. Recorded the finding in rtp-proxy-ADR-016 (Velocity audit (2026-06-13)). The optional proxy companion that holds the channel open without player presence remains a future enhancement, not a tier-1 requirement.
    • [x] 31. Tests where feasible (unit over the framing); the live 2-proxy/2-backend devstack round-trip is acceptance, tracked but not blocking the unit gates. N/A this turn: no proxy-side framing exists to unit-test (Velocity handles the vocabulary natively); the backend-side framing in BukkitNetworkBridge is thin platform glue (would need MockBukkit) and its contract is already covered by PluginMessageNetworkBindingTest via FakeNetworkBridge. The live devstack round-trip stays a separate acceptance turn (plan open item 2).
