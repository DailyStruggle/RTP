    AI Translation Plan - Locale TSV Backfill¶

    Scope: backfill untranslated rows in scripts/out/locale-<lang>.tsv for every shipped locale, prioritising German. Source of truth for the pipeline: AGENTS.md > Locale Config TSV Pipeline. Translation conventions: docs/dev/TRANSLATION_GUIDE.md. Parity guard: LocaleParityTest.

    Generated: 2026-05-29. Data source: scripts/out/untranslated.tsv (537,879 bytes, 7,836 rows).

    Delete this file once the German pass (P1+P2) is submitted and the wider locale sweep has its own checklist.

    1. Scan Summary¶

    untranslated.tsv is produced by the locale-CSV pipeline and rows are categorised as:

    • SAME_KEY - the locale TSV's key column equals base_key (no per-locale rename applied).
    • SAME_VALUE - the locale TSV's value column is byte-identical to the English baseline value.
    • SAME_COMMENT - the locale TSV's preceding_comment column is byte-identical to the English comment block.

    A row may appear in more than one category (e.g. a single English-as-placeholder string typically triggers all three). The category is informational; the translation work is per (locale, relpath, base_key).

    3. Execution Workflow (per locale, per file)¶

    Follows AGENTS.md > Locale Config TSV Pipeline verbatim. Per-locale, per-file slice:

    1. Confirm baseline is current: .\scripts\locale-files-to-csv.ps1 (refreshes scripts/out/*.tsv from on-disk YAML; preserves existing translations).
    2. Reconcile structural parity: .\scripts\reconcile-locale-csvs.ps1 (heals stale placeholders; seeds new rows from English).
    3. Translate scripts/out/locale-<lang>.tsv for the target file slice (filter by relpath):
    4. Mask [placeholders], &a/#hex colour codes, Section markers (section U+00A7), and @type / @range / @unit / @default / @options doc tags to sentinels before machine-translating; unmask after.
    5. Translate value first, then key, then preceding_comment. Leading # on every comment line.
    6. Embed newlines as \n and tabs as \t (same escape rules as baseline.tsv).
    7. Translate from English baseline (base_key / baseline value / baseline preceding_comment) - do not pivot through another locale's translated key, that is a double-translation hazard.
    8. Empty cells fall through to baseline English on regen, so partial passes are safe.
    9. Per AGENTS.md > Markdown Encoding Hygiene: UTF-8 only, no BOM, no Windows-1252 double-encoded mojibake (AeUR", AcoeY..., A..., etc.). For German specifically: emit real ae oe ue ss AE OE UE, never the Windows-1252-misread form.
    10. Mark known-stale rows with # TODO(i18n): comment if a confident translation is not possible.
    11. Regenerate: .\scripts\locale-files-from-csv.ps1 rewrites lang/<locale>/<file>.yml and synthesises <file>.lang.yml. Never hand-edit either.
    12. Verify:
    13. .\gradlew :rtp-plugin:test --tests "*LocaleParityTest*" (must stay green).
    14. .\gradlew build (full build per AGENTS.md > Final Full Build).
    15. Commit the regenerated YAML tree + the edited TSV slice + this checklist update in one commit per slice.

    3.1 AI translation prompt template (per slice)¶

    You are translating Minecraft plugin strings from English to <Target Language>.
Constraints:
  - Preserve all [placeholders] (square-bracketed tokens) and color codes (&a, &7, #2636ef, section-markers) byte-for-byte.
  - Preserve YAML escape sequences (\n, \t) and the leading "# " of every comment line.
  - Preserve @type, @range, @unit, @default, @options doc tags verbatim.
  - Translate only natural-language prose. Do not translate code identifiers, version strings, URLs.
  - Target audience for messages.yml: a player in chat. Use the informal "du" register for German.
  - Target audience for *.yml comments and operator-facing strings: a server administrator. Use the neutral / polite register.
  - Use ASCII hyphen ("-"), colon (":") or parentheses instead of em/en dashes (per AGENTS.md > Markdown Encoding Hygiene rule 7).
  - Output must be UTF-8, no BOM. Emit real "ae oe ue ss" - never Windows-1252 misreads.
Input rows (TSV slice): <paste>
Output: same TSV row layout, only the value / key / preceding_comment columns changed.

    Run one file per slice. After each slice, run step 5 before moving to the next slice. Do not batch multiple locales through the same prompt - the German pass is the model for the others and validates the workflow.

    4. Verification Strategy¶

    • Parity (structural): LocaleParityTest - already green; must remain green after every slice.
    • Spanish content guard: ReqRtpF013SpanishLocaleContentTest - do not edit. If the es pass later trips it, the translation is wrong, not the test.
    • Mojibake sweep: per AGENTS.md > Markdown Encoding Hygiene rule 5, search_project for AeUR, Ac, AcoY, ? (U+FFFD) inside the regenerated lang/<locale>/ tree before commit. Any hit in your diff is a defect.
    • Visual sanity check (German): on a Paper devstack, run /rtp and confirm at least the rotating quick-win strings render in German: alreadyTeleporting, teleportCancel, unsafe, cooldownMessage, queueUpdate.
    • Final full build: .\gradlew build after each locale pass.

    5. Out of Scope¶

    • Adding new baseline keys (that is a separate baseline-edit pass; this plan only translates existing rows).
    • Hand-editing any lang/<locale>/*.yml or *.lang.yml. All edits go through the TSV pipeline.
    • Forge / NeoForge locales (out of project scope, per AGENTS.md > Current Development Focus).
    • Catalan (ca) - not shipped; do not confuse with cat Internet-Cat dialect.
