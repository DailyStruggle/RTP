    CHECKLIST - ADR-048 Menu Builders behind RTPServerAccessor¶

    Effective Issue: Implement ADR-048 - move the five menu page builders from rtp-core/.../common/commands/menu/ into rtp-api/.../menu/builders/ behind four new RTPServerAccessor default methods (menuPermissionProbe, menuEffectivePermissions, menuLocale, menuRegionDescriptor) plus a MenuPlatformView snapshot record. Multi-session task.

    Mode: [CODE] (multi-class, multi-module per Rule D-005; ADR already approved).

    ADR: docs/adr/ADR-048-menu-builders-behind-server-accessor.md (Accepted on user approval 2026-05-23).

    Touch surface: rtp-api (menu/, server/RTPServerAccessor), rtp-core (common/commands/menu/), rtp-bukkit-common, rtp-fabric-common (+ -common-unobf), rtp-plugin (Paper + Fabric command roots).

    Blocking decisions awaiting user approval: none at session start; ADR is Accepted. Flag here if a circular-dep surfaces during step 3 (likely candidate: LangParser pull-up to rtp-api).

    • [x] A2. Add MenuPlatformView record under rtp-api/.../menu/ with static of(accessor, uuid) factory per ADR section 2. Evidence: new rtp-api/.../menu/MenuPlatformView.java (75 lines); canonical constructor null-guards all four components; :rtp-api:compileJava green.

    Session-boundary cues (where to pause cleanly)¶

    If the session runs out of budget, pause at one of these boundaries - each leaves the tree green:

    1. End of Phase A - SPI lands as a no-op change (defaults only). Safe to submit and resume.
    2. End of Phase B - platform overrides land but no caller change. Still safe.
    3. End of Phase C - the big move; the most likely multi-session breakpoint. Both builder copies coexist after C2; safe pause after C2 or after C6.
    4. End of Phase D - Fabric wired; ADR-012 amended. Safe pause.

    Do not pause mid-phase with builder copies in rtp-api but call sites still pointing at rtp-core (between C2 and C3) without either reverting C2 or finishing C3 - that's a split-brain state.

    Resume protocol¶

    On a fresh session:

    1. Re-read this checklist top to bottom.
    2. Re-verify the last [x] item still holds (run_test or compile the affected module).
    3. Re-read ADR-048 for any in-flight clarifications.
    4. Continue from the first [ ].
    5. Re-emit a trimmed version of this checklist in every <UPDATE> so it survives history truncation.
