    CHECKLIST - ADR-076 Config Folder Consolidation¶

    Effective Issue: reduce the operator-facing config surface (12 -> ~7 tiered) by grouping regions/worlds/effects under definitions/, moving schematics/messages under advanced/, and relocating locale rename-maps to co-located dotfile siblings that mirror the English default tree. The lang/ per-locale VALUE tree STAYS at root (user directive 2026-07-27: do not move translated values behind advanced/). Mode: [CODE]. Design locked in ADR-076.

    Key confirmed decisions (from D-005 discussion): - Keep MultiConfigParser kind = regions/worlds/effects; add a separate directory param. - Rename-maps become .<name>.lang.yml co-located beside the file/folder they describe, mirroring the English default folder structure (baseline + per-locale). - Per-locale value trees STAY at root lang/<locale>/, mirroring the full baseline tree internally (so a relocated baseline advanced/messages/ mirrors to lang/<loc>/advanced/messages/). - The legacy TSV pipeline (scripts/locale-files-*.py) is RETIRED / to be replaced; it is no longer a parity gate. LocaleParityTest remains the runtime gate and must stay green. - database/ stays at root (runtime state, not config). - Linux is the assumed deployment (dotfile hiding is acceptable).
