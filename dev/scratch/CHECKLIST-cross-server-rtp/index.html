    CHECKLIST: Cross-server RTP (first end-to-end hop)¶

    Effective Issue: enable a player on backend A to run /rtp (or be routed by a proxy command) and end up on backend B, with reservation token redeemed atomically on arrival.

    Mode: [CODE] (multi-slice, will need D-005 proposals per slice).

    L2. Backend JoinTriggerSource + redeem path (~1d)¶

    • [x] 9. D-005 proposal for L2 - PROPOSAL-cross-server-rtp-L2.md drafted 2026-05-20, approved by user 2026-05-20. Deleted on submit per §9 lifecycle clause.
    • [x] 10. Redeem semantics decided: new redeem.lua + redeem.lua.sha1 sidecar (LF-normalized SHA1 d4ce4939abe5494ea6ea3d81b69056693923b558). Lua returns one of REDEEMED/NOT_FOUND/WRONG_SERVER/ALREADY_CONSUMED/EXPIRED/BAD_STATE; binding maps to RedeemOutcome enum. New SPI method NetworkTransport.redeem(tokenId, playerId, expectedServerId) returns CompletableFuture<RedeemOutcome> (default impl degrades to release+CONSUMED for back-compat).
    • [x] 11. SQL redeem: SqlNetworkStateBinding.redeemSync runs SELECT to classify outcome then UPDATE rtp_network_tokens SET state='CONSUMED', released_at_ms=? WHERE token_id=? AND server_id=? AND player_id=? AND released_at_ms IS NULL AND state IN ('CLAIMED','PENDING') - row-count atomic (affected=1 -> REDEEMED; affected=0 -> ALREADY_CONSUMED). Portable ANSI SQL (H2/Postgres/MySQL/SQLite).
    • [x] 12. HMAC verification reuses findReservationSync (which already calls verifier.verify on the row before returning the token to JoinTriggerSource). Redeem itself does not re-verify because the lookup that found the token id already gated on a valid envelope; an attacker that forges a token id without the envelope cannot make findReservation surface it.
    • [x] 13. New JoinTriggerSource implements Listener at rtp-plugin/.../bukkit/network/JoinTriggerSource.java; subscribes PlayerJoinEvent at MONITOR priority. Folia-aware: the redeem chain runs on the transport's async pool, and the /rtp dispatch hops via RTP.scheduler.runTaskLater(.., 1L).
    • [x] 14. On join: transport.findReservation(uuid) -> if present and serverId matches this backend, transport.redeem(...). On REDEEMED the trigger dispatches Bukkit.dispatchCommand(player, "rtp") (first-cut design - reuses the local pipeline including cooldown / economy / claim / safety; admin-controlled bypass deferred to L5 follow-up per L2 proposal §8 OQ2).
    • [x] 15. Failure paths in JoinTriggerSource.handleRedeem: ALREADY_CONSUMED/WRONG_SERVER -> silent; NOT_FOUND/EXPIRED -> WARNING (player still joins normally, just without bonus teleport); BAD_STATE/HMAC_INVALID/TRANSPORT_ERROR -> WARNING per REQ-RTP-S-004. Configurable MessageKey for cross-server-only player feedback deferred to L5 row 41 per L2 proposal §8 OQ1.
    • [x] 16. NetworkModeBootstrap.boot() instantiates JoinTriggerSource only after a transport opens successfully (i.e. only when network.enabled:true AND a non-empty serverId AND the transport actually opens). RTPBukkitPlugin.setupBukkitEvents calls networkBootstrap.registerJoinTriggerSource(this); with network.enabled:false the field stays null and the call is a no-op.
    • [x] 17. New InMemoryNetworkStateBindingRedeemTest (7 cases): happy path, NOT_FOUND, WRONG_SERVER on serverId mismatch, WRONG_SERVER on playerId mismatch, ALREADY_CONSUMED-via-release, EXPIRED via injected clock, and 16-way concurrent redeem yielding exactly one REDEEMED. All green.
    • [x] 18. :rtp-proxy:rtp-proxy-common:test green + .\gradlew build green (2026-05-20, 1m 57s).
    • [x] 19. Gate: cross-server redeem path is shipped. Token creation already wired in L1 (DefaultRtpDispatcher calls transport.claim from the proxy /rtp handler), so first real cross-server hop is technically possible. Runtime verification of the round-trip is L3 (devstack).
