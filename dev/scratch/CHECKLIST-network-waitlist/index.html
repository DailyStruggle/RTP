    Network Waitlist + Dynamic Batched Dispatch (issue: cross-server rtp should mirror local queue UX)¶

    Effective Issue (one line): when a lobby's cross-server /rtp cannot place a player immediately, park them on a shared Redis-backed waitlist with notify + command-lock + per-backend networkKeptCount-sized batch drain on the proxies, and remove on quit.

    Mode: [CODE]. Scope chosen by user: C1 = Slice 1 only this session. Slices 2-5 are explicit follow-ups (own sessions).

    Slice 3b (landed 2026-05-21)¶

    • [x] 3b.1 Authored 7 Lua scripts under rtp-proxy-common/src/main/resources/redis/: waitlist_enrol.lua, waitlist_peek.lua, waitlist_drain_batch.lua, waitlist_position.lua, waitlist_remove_uuid.lua, waitlist_reap.lua, waitlist_refresh_ttl.lua. Each ships with an LF-normalized SHA1 sidecar. waitlist_peek is a non-mutating LRANGE helper; the drain protocol is peek + client-side per-backend allocation + atomic waitlist_drain_batch LREM under the WaitlistLeaderLease single-drainer guarantee.
    • [x] 3b.2 Added RedisNetworkWaitlist (549 lines) under rtp-proxy-common/.../transport/redis/. Mirrors RedisNetworkRequestQueue's JedisPool + single-thread executor + AutoCloseable skeleton. Hand-rolled minimal JSON encoder/decoder for WaitEnvelope (avoided a Jackson dep). Keyspace: rtp:net:waitlist:list / :uuids / :cids.
    • [x] 3b.3 Added no-Redis RedisNetworkWaitlistScriptLoadTest (1 case): verifies all 7 sidecars match LF-normalized script bytes via RedisLuaScripts.load(...). Green via run_test.
