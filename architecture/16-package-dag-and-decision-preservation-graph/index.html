    Core Package Architecture and Decision Traceability Map¶

    Scope of this document. This document specifies and visualizes the package hierarchy, structural decoupling boundaries, and decision traceability hypergraph for rtp-core. It models the module's 4-tier Directed Acyclic Graph (DAG), diagrams the decoupled seams that eliminate cyclic package tangles, and specifies the closed hypergraph connecting implementation classes to governing ADRs, absolute prohibition requirements (S-001..S-007), and automated verification tests.

    Companion architectural decisions and references: - ADR-000: Development Workflow and D-005 Guard Rail. - ADR-001: Archimedean Spiral 1D Mapping. - ADR-008: MemoryTracker as Active Task GC. - ADR-015: Stale-Chunk Guard for Count-Bound Pipes. - ADR-016: Anvil Read-Only Subsystem. - ADR-094: Quality-Engineering Gates and ArchUnit Enforcement. - ADR-110: Purpose-Gated Live Loads. - ADR-112: Per-Region Work Division on Folia. - ADR-114: Cost-Governed On-Demand Chunk Reads. - ADR-115: Package DAG Disentanglement and Finite Decision-Preservation Hypergraph (Authoritative Decision). - docs/dev/REQUIREMENTS.md: Absolute Prohibition Requirements (S-001 through S-007). - docs/dev/TRACEABILITY.md: Requirements to Code and Test Traceability Matrix.

    Executive Overview (Package DAG & Decision Hypergraph)¶

    The rtp-core module implements the platform-neutral coordinate math, memory tracking, multi-tier chunk resolution, and teleport execution pipelines. The architecture is structured around two governing models:

    1. Acyclic Package Layering (0.0% SonarQube Package Tangles): The packages in rtp-core are organized into a 4-tier Directed Acyclic Graph (DAG). Dependencies flow strictly downward (Tier 4 $\to$ Tier 3 $\to$ Tier 2 $\to$ Tier 1). Elimination of cyclic package tangles ensures that domain algorithms (such as MemoryTracker and LocationGenerator) operate as isolated, self-contained components without coupling to the plugin composition root or presentation layers.

    2. Finite Decision Hypergraph (Code $\longleftrightarrow$ ADR $\longleftrightarrow$ Requirement $\longleftrightarrow$ Test): Implementation invariants (including Archimedean spiral indexing, Anvil pre-filter deduplication equations, and weak-reference garbage collection sweeps) link directly to their governing design records. Classes declare their governing ADRs, prohibition requirements, and operational invariants in structured Javadoc headers, establishing a closed, traceable graph from requirement to automated verification.

    Tier Specifications¶

    • Tier 1 (Foundation & Schemas): Contains pure data schemas, configuration records, domain enums, primitive spatial math tables, and lifecycle contracts. Classes in Tier 1 shall have zero dependencies on other rtp-core packages.
    • Tier 2 (Domain Engines & Storage): Contains core mathematical engines and state managers: Archimedean spiral and Hilbert spatial memory (MemoryShape), resource tracking (MemoryTracker), database accessors (DatabaseAccessorFactory), and concurrency governors (ImmediateLoadGovernor). Classes in Tier 2 depend strictly on Tier 1 contracts and schemas; they shall contain no references to command execution, player messaging, or presentation layers.
    • Tier 3 (Execution Pipelines & Coordination): Contains runtime task orchestrators and asynchronous pipelines: player teleport pipelines (TeleportPipelineTask), background queue pre-generation (PregenTask), scan crawlers (ScanTask), scripted action execution (ActionManager), and network synchronization. Depends on Tier 2 domain engines and Tier 1 foundation contracts.
    • Tier 4 (Orchestration & Ingress): Contains user-facing and external entry points: command dispatch trees, interactive book menus, web editor channels, event bridges, and the plugin composition root (RTP.java). Depends downward on Tiers 3, 2, and 1. Zero core packages shall depend on Tier 4.

    2. Structural Seam Decoupling Patterns¶

    The 4-tier DAG resolves cyclic dependencies across packages by decoupling four critical structural seams:

    1. Task Execution vs. Resource Safety (tasks.teleport $\longleftrightarrow$ tools)¶

    Pattern: Interface Extraction. - tools.MemoryTracker manages resource lifecycles and garbage collection sweeps without coupling to the concrete execution details of TeleportPipelineTask. - tools.contracts.TrackableTask defines the lifecycle contract (UUID id(), isCompleted(), getReservations(), cancel()). - TeleportPipelineTask implements TrackableTask. MemoryTracker interacts strictly through the contract, isolating Tier 2 from runtime execution in Tier 3.

    2. Command Tree Inversion (commands $\longleftrightarrow$ commands.*)¶

    Pattern: Shared Base & Provider Registration. - Root command infrastructure (BaseRTPCmd, parameter parsers) resides in commands.base (or leverages commands-api). - Concrete subcommands (commands.admin.AdminCmd, commands.config.ConfigCmd) depend downward on commands.base. - Subcommands register into the tree dynamically or via provider collections, ensuring child subcommands do not import the parent composition builder.

    3. Domain Models vs. Runtime Pipelines (selection.region $\longleftrightarrow$ tasks)¶

    Pattern: Separation of Schema & Pipeline Coordination. - Region functions as a calculation manifold operating on immutable configuration schemas (RegionConfigRecord) defined in Tier 1. - Teleport execution pipelines are dispatched by Tier 3 coordinators (QueueRefillCoordinator), avoiding direct task invocation inside domain calculation classes.

    4. Composition Root vs. Global State (common.RTP)¶

    Pattern: Context Encapsulation & Constructor Injection. - RTP.java operates strictly as a Tier 4 Composition Root: it instantiates and wires subsystems during startup, and tears them down during shutdown. - Internal domain classes receive required SPI services (RTPScheduler, RTPServerAccessor, MemoryTracker) via constructor parameters or a scoped RTPContext. - Classes in Tiers 1, 2, and 3 shall contain no static references to RTP.java.

    Standard Class Invariant Header Format¶

    Safety-critical classes declare their governing constraints using standardized Javadoc tags:

    /**
 * Enforces per-region and global concurrency bounds on native chunk generation
 * during on-demand (LoadPurpose.IMMEDIATE) teleport execution.
 *
 * @governedBy ADR-110 (Purpose-Gated Live Loads)
 * @governedBy ADR-114 (Cost-Governed On-Demand Chunk Reads)
 * @trace REQ-RTP-S-004
 * @trace REQ-RTP-S-005
 * @invariant S-005: Zero synchronous chunk loading or blocking calls on the main/tick thread.
 * @invariant Concurrency-Cap: Maximum 1 concurrent generation permit per region, 2 server-wide.
 * @invariant Fail-Visibility: Requests timing out after 1200ms shall complete with msgBusy (S-004, S-007).
 * @prohibition DO NOT remove semaphores to "speed up" concurrent player teleports; unbound
 *              live chunk generation causes severe main-thread tick stalls and watchdog crashes.
 */
public final class ImmediateLoadGovernor {
    // ...
}

    Tag Invariant Definitions¶

    • @governedBy ADR-NNN: Declares the authoritative architectural decision record defining the engineering trade-offs and rationale.
    • @trace REQ-MODULE-FAMILY-NNN: Declares the functional or non-functional requirement satisfied by the component.
    • @invariant S-00x: Declares compliance with non-negotiable absolute prohibition requirements (S-001 through S-007).
    • @invariant <Name>: Declares mathematical, operational, or concurrency invariants (e.g., concurrency bounds, non-mutating reads).
    • @prohibition: Declares explicit negative constraints defining operations that refactoring shall not introduce.

    4. ArchUnit Verification Guardrails¶

    Package acyclicity and tier separation are verified mechanically during the build by RTPArchitectureTest (rtp-core/src/test/java/.../RTPArchitectureTest.java):

    public class RTPArchitectureTest {

    @ArchTest
    static final ArchRule packages_must_be_free_of_cycles =
            slices().matching("io.github.dailystruggle.rtp.common.(*)..")
                    .should().beFreeOfCycles()
                    .because("Package tangles break modularity and prevent isolated component testing.");

    @ArchTest
    static final ArchRule domain_engines_must_not_depend_on_orchestration =
            noClasses().that().resideInAnyPackage("..selection..", "..tools..", "..database..")
                    .should().dependOnClassesThat().resideInAnyPackage("..commands..", "io.github.dailystruggle.rtp.common")
                    .because("Domain engines in Tier 2 shall not have upward dependencies on Tier 4 orchestration.");

    @ArchTest
    static final ArchRule foundation_must_have_zero_outgoing_core_dependencies =
            classes().that().resideInAPackage("..configuration.schema..")
                    .should().onlyDependOnClassesThat().resideInAnyPackage("..configuration.schema..", "..configuration.enums..", "java..")
                    .because("Tier 1 Foundation schemas shall be completely free of domain and runtime dependencies.");
}
