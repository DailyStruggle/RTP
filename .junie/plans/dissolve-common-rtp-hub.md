# Technical Design

### Current Implementation
- Measured top-level sizes: `devstack` 14.58 GiB, `testdata-world` 1.27 GiB, `.gradle` 0.92 GiB, `platforms` 0.39 GiB (mostly `build/`), `build` 0.25 GiB, `rtp-core` 0.18 GiB, `.git` 0.16 GiB. Everything else is under 0.15 GiB.
- Most of `devstack/` is world data under container mounts. `devstack/.gitignore` already ignores these paths (`sweep/`, `**/world*/`, `**/cache/`, `**/plugins/.paper-remapped/`, `legacy/*/config/`, and so on). Only 73 files under `devstack` and `testdata-world` are tracked.
- The root `.gitignore` ignores `/testdata-world/` (l.185), `/.gradle/` (l.135) and `/build/` (l.136). Benchmark tests such as `TwoTierRouterWorldDataBenchmarkTest` and `HeuristicPlannerBenchmarkTest` use `assumeTrue` and skip when the save is missing. `LinearRealDataParityTest` also checks `Files.isRegularFile` before reading it.

### Key Decisions
1. **The candidate list comes from git, not from guesses.** `git ls-files --others --ignored --exclude-standard --directory` lists the ignored paths. I keep only those that match the purge categories in Requirements, then remove anything matching the keep list (`*.bak`, `scripts/tmp*`, `devstack/logs`, `.env`, `*.secret`, `devstack/shared/lobby-world*`, `devstack/jars`, `.idea`, `.junie`, `.qodana`). For each remaining candidate, `git ls-files -- <path>` must return 0 files.
2. **Dry run first.** The manifest (each path and its size) goes to the session scratch dir (`$env:JUNIE_TMPDIR`), not into the repo. I delete only paths that are in the manifest.
3. **No `git clean`.** The project guidelines forbid it. Deletion uses a stdlib Python `shutil.rmtree` one-liner with the `\\?\` long-path prefix and an `onerror` handler that clears read-only bits. That handles the `Filename too long` paths under `build/reports/tests` and read-only files in `node_modules`. Any path that fails is reported, not skipped silently.
4. **Gradle outputs go last, and only if no Gradle run is active.** Deleting `.gradle/` or `build/` under a live run would corrupt it, and the guidelines say never to interfere with another agent's run. If PID 131560 or a wrapper lock is still active, that step is skipped and reported, leaving about 1.9 GiB that you can exclude from the backup instead (e.g. `robocopy /XD build .gradle`).
5. **Containers stay down.** If `docker ps` shows any devstack container running, the devstack step stops before deleting anything under its mounts.

### Risks
- **`testdata-world/` is permanent loss.** You approved this. Afterwards the world-data benchmarks skip, and `LinearRealDataParityTest.multiChunkRealWorldParity` returns early. I'll add a line to `docs/dev/RTP-HUB-RESUME.md` so a resuming agent doesn't mistake those skips for a regression.
- **Devstack worlds hold seeded state:** acceptance scenarios rebuild it on boot. The first run after the reinstall will take longer (world generation and Paper remap).
- **Windows file locks:** an IDE indexer or a Gradle daemon may hold files in `build/`. Locked paths get reported and left in place.

# Testing

### Validation Approach
No builds are run: they would recreate `build/` and `.gradle/`, and nothing here changes code. Verification compares a snapshot of the keep set taken before the purge with one taken after:
- `git status --porcelain=v1 -uall` (tracked and untracked, not ignored): it must be byte-identical before and after.
- `git diff --cached --stat` and `git diff --stat`: both must be identical.
- The count and total size of `*.bak` files, plus the file list of `scripts/tmp/`, `devstack/logs/` and `rtp-core/src/main/java/.../common/runtime/`: all must be identical.
- Total size of the tree, with per-top-level sizes, from the same `os.walk` pass as the baseline.

### Edge Cases
- A candidate that contains a tracked file is dropped. The dry run shows any that were.
- If a Gradle run or container is active, that step is skipped and reported, not forced.
- Paths that fail to delete (long path, lock, permissions) are listed with the error.
